## Prompt: Multi-Gym Management SaaS Application

**Build a modern, scalable, multi-tenant Gym Management System (SaaS platform)** where **multiple gyms can register under one platform** and be managed independently.

The platform must support:

### Tech Stack

* **Frontend:** React.js + Vite
* **UI Framework:** Tailwind CSS + ShadCN UI
* **Icons:** Lucide React / Font Awesome
* **State Management:** Zustand or Redux Toolkit
* **Backend:** Supabase (preferred) or Firebase (free tier alternative)
* **Authentication:** Supabase Auth (Email, Google Login)
* **Database:** PostgreSQL (Supabase)
* **Storage:** Supabase Storage
* **Realtime Features:** Supabase Realtime
* **Charts & Analytics:** Recharts
* **Notifications:** Email + SMS integration (free-ready architecture)
* **Deployment:** Vercel (frontend) + Supabase backend

# System Type

Create a **multi-tenant SaaS Gym Management System** where:

### 1. Super Admin

The **Super Admin controls the entire platform** and can:

* Register/manage multiple gyms
* Approve or suspend gyms
* Manage subscriptions/plans
* View all gym analytics
* Revenue monitoring
* Platform settings
* Role management
* Security & backups
* View all gym performance
* Send announcements to gym owners

---

### 2. Gym Owner (Tenant Admin)

Each registered gym gets its **own isolated dashboard and database access scope**.

Gym Owners can manage only their gym:

#### Dashboard

* Revenue overview
* Active members
* Attendance
* Trainers
* Equipment status
* Membership renewals
* Notifications
* Class occupancy
* Analytics charts

# Multi-Tenant Architecture

Each gym should have:

```sql
gym_id
```

All records must be tenant-scoped:

```sql
members
trainers
attendance
payments
classes
workouts
equipment
notifications
staff
```

Every table must include:

```sql
gym_id UUID
```

to isolate gym data.

**Security Rule:**

Gym owners can access **only their own gym data**.

Implement **Supabase Row Level Security (RLS)**.

Example:

```sql
gym_id = auth.jwt()->>'gym_id'
```

No gym owner should ever see another gym’s data.

# User Roles

Implement role-based access:

### Super Admin

Full platform access.

### Gym Owner

Full access to own gym.

### Staff

Limited operational access.

### Trainer

Workout & member training access.

### Receptionist

Attendance + billing only.
